## 3. 표 형식 (모든 과제가 같은 형식을 쓴다)

폴더: `/home/leejaeik/Projects/ksat-10000/tools/glyph/`

### 3-1. 한양 PUA
- `hanyang_pua.json`: `{"version": 1, "source": "hypua2jamo 0.7 (composed)", "map": {"E0BC": "<첫가끝 문자열>", ...}}` — 5,661코드. 값에 NFC를 걸지 않는다.
- `hanyang_fonts.json`: `{"version": 1, "fonts": [{"font": "^Haansoft-?Batang$", "evidence": {...검증 수치...}}, ...]}` — 이 정규식에 맞는 글꼴의 PUA만 한양 표로 바꾼다.

### 3-2. 글꼴별 대응표 `tbl_<이름>.json`
```json
{
  "version": 1,
  "family": "HyhwpEQ",
  "font": "^HyhwpEQ$",
  "key": "ucs",
  "entries": {
    "E035": {"text": "2", "status": "확정", "pos": "base", "role": "char", "style": "upright", "desc": "", "n": 1200}
  }
}
```
- `font`: 꼬리표를 뗀 글꼴 이름에 맞추는 정규식. 한 글꼴 이름은 표 하나에만 맞아야 한다(여러 굵기·기울임을 한 표에 넣을 때는 `entries`의 열쇠를 `"<글꼴 이름>|<코드>"`로 쓰고 `"key": "font|ucs"`).
- 열쇠의 코드는 PDF 글자층에서 뽑힌 유니코드 값(4자리 이상 대문자 16진수). ASCII로 뽑히는 글리프도 **전부** 넣는다(멀쩡해 보이는 `<`가 실제로는 ≤일 수 있다).
- `text`: 그 글리프가 뜻하는 표준 유니코드 글자(여러 글자 가능). `status`: `확정`(정확히 대응하는 유니코드가 있고 눈으로 확인함) / `근사`(정확한 유니코드가 없어 가장 가까운 표기를 씀. 예: 네모 안 숫자 → `[1]`) / `미확정`(모름·모호함. `text`는 빈 문자열).
- `pos`: `base`/`sup`/`sub`(글리프 자체가 위·아래 첨자 모양으로 만들어진 경우). `role`: `char`/`bar`(분수선·윗줄)/`radical`/`piece`(큰 괄호 조각 등)/`space`. `style`: `upright`/`italic`/`bold`/`bolditalic`. `desc`: 모양 설명(한국어). `n`: 전수에서 나온 횟수.
- 같은 (글꼴, 코드)인데 서로 다른 모양이 섞여 나오면 `미확정`으로 두고 `desc`에 적는다.

### 3-3. 눈 확인 근거 (나중에 Opus 카드가 독립으로 다시 본다)
- `tools/glyph/evidence/<이름>/blind_NN.png`: 칸마다 칸 번호와 글리프 그림(단독 그림 + 실제 쪽에서 앞뒤 글자와 함께 잘라 낸 그림)만. **대응 결과·후보 글자는 그리지 않는다.** 한 장에 30~48칸, 글리프가 또렷이 보이는 크기.
- `tools/glyph/evidence/<이름>/cells_NN.json`: `{"1": {"font": "...", "code": "E035", "n": 1200, "pdf": "<raw 기준 상대 경로>", "page": 3}, ...}`.
- 눈 확인은 이 그림을 vision으로 직접 보고 한다. 모양만으로 모호하면(− 와 –, x 와 ×, ′ 와 ') 문맥 그림으로 정하고, 그래도 모호하면 `미확정`.

### 3-4. 코드 값의 기준 (도구와 표가 어긋나지 않게)
- 표에 적는 코드는 **`page.get_texttrace()`가 주는 `ucs` 값**이다(글자마다 `(ucs, gid, origin, bbox)`, span마다 `font`·`size`). `get_text('rawdict')`는 설정에 따라 모르는 글자를 CID 값으로 바꾸거나 합자를 풀 수 있으므로, 표를 만들 때도 도구가 바꿀 때도 texttrace 값을 기준으로 삼는다.
- U+FFFD로 뽑히는 글리프는 코드로 구별할 수 없으니 `미확정`으로 두고 횟수만 보고한다.
- 전수·그림 작업은 `nice -n 10`으로, 동시에 4개 프로세스 넘지 않게 돌린다(칸반 작업자가 같은 PC에서 돌고 있다).
