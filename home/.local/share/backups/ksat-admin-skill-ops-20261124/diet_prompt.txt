[계획-진행] [마스터 결정] 총괄 운영 줄이기(인수 검사 도구·시작 확인·원장 기록)

먼저: 이 메시지 직전에 처리 중이던 알림은 마저 끝낸다. 실행 중인 카드는 끊지 않는다.

1. 결정
- 오늘 변경 뒤 Codex에서 총괄 몫이 읽은 양 기준 81%에서 25%로 내려갔다. 남은 몫을 더 줄이려고 카드마다 하던 확인과 기록을 줄인다. 내용 판단은 그대로다.
- 미쿠가 읽기 전용 검사 도구 tools/accept_check.py를 넣었다(칸반 DB와 작업자 세션 DB를 읽기만 하고 아무것도 쓰지 않는다. 오늘 끝난 카드 49장으로 시험했다).
- 미쿠가 공통 기준 v6의 2절 두 문장을 5절 3번에 맞추고 1절에 '묶음마다 저장' 한 줄을 넣었다. 판 이름은 v6 그대로이고 SHA256은 c43b555e5ae40f76f3a7c229c82d44d035dd4e8aac89aff82cc731bdec395c33다.

2. 할 일
1) 스킬 3절 맨 앞에 다음 네 문장을 글자 그대로 넣고, 3절 4~7번과 다른 곳의 어긋나는 요구(작업자 세션 DB로 모델·응답·도구 활동 확인, 시작 때 구독·예약·기준 문서 재확인, 인수 때 해시 루프 직접 작성, 시작·감시·무조치 점검의 원장 기록)를 여기에 맞게 고친다.
"카드 시작은 두 번에 끝낸다. 한 명령에 사용량 조회·겹침 대사·카드 만들기·구독·실행 댓글·unblock을 묶고, 다음 명령에서 show로 running과 run 번호를 한 번 본다. 작업자 세션 DB, 구독, 예약, 기준 문서는 시작할 때 다시 보지 않는다. 시작 실패는 감시 사건(blocked·crashed·gave_up)으로 받는다."
"인수는 인계 문서를 읽고 /usr/bin/python3 -B tools/accept_check.py <카드 ID>를 한 번 실행한다. 끝 줄이 '판정: 일치'면 manifest·파일·입력 SHA256·실제 모델 확인은 끝난 것이며 해시 루프나 세션 조회를 따로 하지 않는다. '불일치'나 '검사 불가'면 그 줄에 적힌 것만 직접 확인한다."
"보통의 카드에 다는 총괄 댓글은 실행 댓글 하나와 인수 댓글 하나다(계획서가 따로 시킨 댓글은 그대로). 원장에는 계획서 7절의 운영 결정, 단계 완료, 마스터 결정 반영만 한 줄(200자 안쪽)로 적는다. 정한 순서대로 다음 카드를 시작한 것, 감시 교체, 조치 없는 점검은 원장에 적지 않는다."
"예약 상태와 기준 문서(AGENTS.md·계획서·공통 기준)의 SHA256은 30분 예약 실행에서만 확인한다."
2) 30분 예약 실행에도 같은 기준을 쓴다. 예약 프롬프트는 고치지 않는다. 그 프롬프트의 '로컬 확인 기록'은 예약 출력으로 갈음하고, '실제 모델 응답·도구 활동 확인'은 인수 때 도구로 갈음한다.
3) 도구를 끝난 카드 하나에 돌려 출력을 확인한다. 이상하면 쓰지 말고 출력 그대로 보고한다.
4) 원장 t_729e2d91에 "[마스터 결정 반영] 총괄 운영 줄이기(인수 검사 도구·시작 확인·원장 기록)" 댓글 하나를 다섯 줄 안쪽으로 남긴다.
5) 고친 문장과 도구 시험 결과를 짧게 보고한다.
