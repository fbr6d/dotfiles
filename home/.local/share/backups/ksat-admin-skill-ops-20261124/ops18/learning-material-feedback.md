# 학습자료 피드백 접수·정정·변경 인계

## 적용 범위

학습지 사진에서 임시 보고안을 만들거나, 사용자가 자료 품질과 실제 학습을 구분해 피드백하거나, 그 피드백을 진행 중인 제작과 후속 자료에 전달할 때 사용한다. 설명 말투의 기본 기준은 SKILL.md를 따른다. 자료의 정확성·복기 번호 연결 검사는 `source-grounded-wiki.md`의 학습자료 대사 절을 함께 적용한다.

## 1. 기록 용도를 확인한 뒤 전사한다

1. 사용자 메시지와 대상 자료의 판본·쪽을 먼저 읽는다. **자료 품질 점검 / 실제 학습 / OCR 정정용 임시안**을 구분하고 용도가 불분명하면 성취나 진도부터 판정하지 않는다. 같은 숫자라도 점검에 쓴 시간과 실제 학습 시간은 서로 다른 자료다.
2. 첨부 사진은 이미지 도구로 직접 읽고 작은 숫자·자모·선지 기호·지우거나 덧쓴 글씨만 필요한 영역을 확대한다. 인쇄된 선택지와 실제 동그라미 선택, 빈칸과 미실시를 구분한다. 내용이 자연스럽다는 이유로 안 보이는 글자를 채우지 않는다.
3. 임시안에는 읽힌 내용을 항목별로 정리하고 불확실한 부분을 `[확인 필요: …]`로 표시한다. 사용자의 오독·계산·발음 표기를 추정 정답으로 고치지 않는다. 총시간·점수·통과 여부의 빈칸도 임의 계산이나 해석으로 채우지 않는다.
4. 사용자 수정본이 오면 그 원문을 최신 입력으로 삼는다. OCR 문구와 정정 문구를 섞지 않으며, 후속 정정으로 기록 용도가 바뀌면 용도부터 다시 분류한다. OCR 정정 완료는 실제 학습 완료의 증거가 아니다.

## 2. 카드에 원문과 현재 판정을 함께 기록한다

1. 먼저 요청 ID 또는 tenant로 목록을 줄인 뒤 `hermes kanban --board ksat-10000 show <카드ID> --json`에서 현재 상태·결과·최신 관련 댓글·완료 run의 메타데이터만 추린다. 긴 JSON은 도구 반환 뒤가 아니라 **CLI에서 먼저 필터링**한다. 예: `hermes kanban --board ksat-10000 list --json | jq -ce --arg tenant "$tenant" '[.[] | select(.tenant==$tenant) | {id,title,status,assignee}]'`. 절단되거나 깨진 응답을 관대한 JSON 복구로 이어 붙여 쓰기 근거로 삼지 않는다. 완전한 JSON인지 엄격히 검사하고, 갱신 전에 요청 ID 집합·대상 수·담당을 대조한다. 불일치하면 원래 값을 보정하지 말고 해당 대상만 작게 재조회한다. 단순 기록 갱신을 무관한 실행 이력·환경 전체 조사로 넓히지 않는다.
2. 사용자 제출 원문·근거 메시지·자료 판본과 쪽·기록 용도를 댓글로 남긴다. 수정할 때는 이전 분류의 무엇을 철회하고 무엇으로 대체했는지 명시한다. 원댓글을 지워 이력을 바꾸지 않는다.
3. 댓글만 고치고 최신 요약·결과·메타데이터에 반대되는 판정을 남겨 두지 않는다. 예를 들어 품질 의견만 접수됐으면 실제 학습 후 피드백은 여전히 미접수이며, 사용자가 실제 학습 미실시로 정하면 단순 미검증보다 그 명시적 분류를 우선한다. 자료 인수 카드의 완료 상태를 사용자 학습 완료로 확대하거나, 피드백을 적기 위해 제작 작업자를 재가동하지 않는다.
4. 완료 카드의 요약·메타데이터를 갱신할 때는 응답의 실제 키·자료형과 기존 결과를 먼저 확인해 보존한다. 현재 응답에서 결과가 `.task.result`, 실행 메타데이터가 `.runs[-1].metadata`처럼 서로 다른 위치에 있을 수 있으므로 `.runs[-1].result`를 문자열로 가정하지 않는다. 기존 값이 `null`이면 문자열 추출 실패를 결과 부재의 새 오류로 만들지 말고 원래 `null`을 JSON 값으로 보존한다. `hermes kanban --board ksat-10000 edit <카드ID> --result '<이전 결과와 후속 정정>' --summary '<현재 판정>' --metadata '<기존 필드에 최신 판정을 병합한 JSON>'`처럼 함께 전달한다. CLI 인수 조합은 현재 `edit --help`와 대조한다. 원문이 길면 한 전경 셸 호출 안에서 `data=$(hermes kanban --board ksat-10000 show "$card" --json)`로 완전한 응답을 받아 `jq -e`로 기존 필드를 추출·병합하고, 도구에는 검증용 요약만 출력한다. 절단된 표시용 응답으로 기존 본문·결과·메타데이터를 재구성하지 말라. 일부 필드만 담은 객체로 덮어쓰면 인수 해시·검수 이력·다른 과목의 원장이 사라진다.
5. 같은 카드를 재조회해 원문 보존, 최신 분류, 남은 실제 학습·피드백, 카드 상태가 일치하는지 확인한다. 반환에 없는 댓글 번호를 만들어 인용하지 말고 실제 제공된 식별자나 근거 메시지로 추적한다.

## 3. 수정과 후속 기준을 구분해 제안한다

- **설명·양식 보강 후보:** 자료 설명만으로 필요한 규칙을 찾기 어렵거나 복기 항목을 번호로 지목할 수 없으면 현재 자료의 설명·연결·보고란을 최소 범위로 보강하는 안을 제시한다. 내용 정확성 검수 통과와 실제 사용성은 별도 판단이다.
- **대조 후 판단할 항목:** 기호 위치·표기 혼동·가독성은 원문과 판독 상태부터 확인할 대상으로 둔다. 보고된 혼동만으로 정답·원문 오류를 확정하거나 원문을 고쳐 쓰지 않는다.
- **이후 제작 기준:** 설명·복기·대조표·피드백의 번호 대응, 원문과 계산의 분리, 기록 용도 구분, 쉬운 말투와 암기 지원 절차를 후속 명세에 넣을 후보로 정리한다. 정리한 기준과 실제 산출물에 적용·검수한 결과를 구분한다.
- **승인 경계:** 현재 자료의 추가 수정과 이후 자료 제작 기준의 적용, 실제 학습 진도 변경을 각각 구분한다. 같은 제작자·검수자, 쓰기 경로, 변경·비변경 범위, 남은 수정 회차와 완료 기준을 제시한다. 수정 한도가 이미 사용됐다면 새 사용자 승인 없이 추가 수정 카드를 만들지 않는다. 별도 추가 보강 승인이 있으면 그 승인에 한정된 회차로 관리하고 이전 수정 이력은 유지한다.

## 4. 추가 요청을 현재 회차와 후속 제작에 인계한다

1. 현재 제작·검수 카드가 준비 중인지, 실행 중인지, 제작 완료인지 먼저 확인한다. 추가 요구라면 준비 명세나 진행 댓글에 전달하고 승인된 회차 안에서 반영한다. 사용자가 중지·취소·미수정 보존을 지시했다면 그 범위의 실행부터 멈추거나 대기 해제 가능성을 제거하고, 아래 7절에 따라 정리한다. 관련 없는 새 계획·예약·작업자까지 중단하지 않는다. 이전 제작 허가는 최신 중지 지시를 무효화하지 않는다.
2. 제작자에게 새 기준을 전달하고 실제 반영 위치·판본을 인계받는다. 독립 검수 단계가 이미 승인된 대상에는 해당 검수자에게도 같은 기준을 전달해 정의·조건·변경 쪽의 조판 영향을 확인하게 한다. 마스터 선확인 전인 학습 PDF에는 이 전달을 이유로 AI 최종 검사를 먼저 배정하지 않는다. 실행 중 본문·댓글 편집의 성공과 작업자의 실제 수신·적용은 별도로 확인한다.
3. 인계물에 반영한 항목·위치·판본과 실제 설명 예시 한 단락을 요구한다. 총괄이 직접 제시한 기준 문장이나 초안은 완성 PDF 발췌라고 부르지 않는다.
4. 이후 자료의 기본 기준으로 적용하라는 승인까지 있으면 실제 후속 카드·승인된 예약 지시 등 작업자가 읽는 경로에 전달한다. 다른 프로필의 기억이 자동 갱신됐다고 가정하지 않는다. 기존 예약을 앞당겨 실행하는 경우 원래 산출물별 중복 방지 키를 재사용하고 이미 만든 카드의 최신 명세를 읽게 한다.
5. 예약 지시만 갱신하는 경우에도 변경 전후 예약 시각·횟수·전송 대상·모델·활성 상태를 대조한다. 문체 인계 요청을 전체 일정 재설계나 새 예약 생성 권한으로 확대하지 않는다. 마지막에는 카드별 전달 상태와 실제 적용 검증 여부, 필요한 승인만 한 번에 보고한다.

## 5. 현재 프런트엔드에서 직접 인수·보고할 때

1. 사용자가 작업자 재실행 없이 총괄의 직접 마무리를 지정하면 이미 수행된 인수 대조·수정·검수 근거를 먼저 읽는다. 전체 검사를 다시 하거나 임시 실행자를 띄우지 않는다.
2. 사용자가 특정 사전 확인을 생략하도록 결정하면 생략한 단계와 근거를 기록한다. 같은 목적의 명령을 다른 형태·도구로 바꾸어 재실행하지 않는다. 단계 삭제는 차단 명령 실행이나 보호 설정 변경의 승인이 아니다. 외부 API로 새 게시를 수행하는 경우의 정확한 대상·게시 결과 검증 의무는 별도로 적용한다.
3. 이 대화에서 보고하도록 요청받았으면 정해진 머리말로 실제 최종 본문을 먼저 제시한다. 로컬 PDF 경로·쪽수·실제 검수 흐름·필요한 회고와 남은 사용자 작업을 담고, 자동 사건 알림이나 보고문안 준비로 최종 보고를 대신하지 않는다.
4. **종료만 필요한 카드가 다시 실행되지 않게 한다.** 최신 run이 끝났고 실제 소유권 충돌이 없는지 확인한다. 사용자가 완료만 요청했고 지원되는 인터페이스가 차단 상태의 직접 완료를 허용하면 불필요한 `unblock` 없이 닫는다. `unblock → complete`를 명시했다면 자동 디스패치 가능성을 먼저 확인한다. 이때 지원되는 `assign <카드ID> none`으로 잠시 배정을 비우는 경로를 쓸 수 있으나, `kanban.default_assignee` 등 대체 자동 배정이 없는지 확인해야 한다. 검증된 경로에서 같은 전경 호출로 해제·완료하고 완료 후 원래 추적 담당을 복구한다. 별도 `dispatch`나 전역 디스패처·보호 설정 변경은 하지 않는다. 다른 살아 있는 소유자를 무시해 강제 완료하지 않는다.
5. **완료 기록과 작업자 실행을 구별해 재조회한다.** 수동 `complete`도 새로운 종료 run을 남길 수 있고 그 `profile`이 비어 있지 않을 수 있다. run 개수 증가나 프로필 이름만으로 재실행을 판정하지 말고 이전 관측 경계 뒤의 `spawned`·`owner_admitted`·`worker_bound`와 실제 소유권을 대조한다. 검증 파서가 실패하면 먼저 같은 카드의 현재 상태를 다시 읽고, 이미 성공한 완료·게시·취소를 반복하지 않는다.
6. 마지막 `list`에서 잔여 차단을 실제 집계해 요청한 수준으로 알린다. 카드 종료와 사용자 품질 승인·실제 학습·실물 인쇄의 남은 상태를 구분한다.

## 6. 사이클별 문항 사용 원장을 마련하고 교체에 인계한다

1. **적용 시점과 원장 위치를 고정한다.** 최신 사용자 지시에서 사이클의 단위, 현재 자료의 유지 조건, 교체가 시작되는 사이클, 품질 승인 판단 시점을 읽는다. 기존 카드·원장·승인된 후속 예약에 같은 경계를 전달한다. 원장은 승인된 단일 Kanban 기록의 `feedback_cycle_item_registry` 같은 구조화 필드와 설명 댓글로 관리할 수 있다. 실제 카드 ID·사이클 현황은 프로젝트 기록에 두고 스킬에 복사하지 않는다. 기준 기록 요청을 `AGENTS.md`·계획서 수정이나 다음 사이클 실행으로 임의 확대하지 않는다.
2. **현재 수록 목록을 원래 값 그대로 등록한다.** 승인된 JSON 읽기 방법으로 과목별 `source-manifest.json`의 `version`, `task_id`, `questions`를 읽고 사이클 ID·과목·판본·담당 카드·수록 상태를 붙인다. 문항마다 `question_id`, `original_code`, 원문 번호/단원, 출처 기관·교재/시험·학년도/발행연도·판본/책형, 원문 경로/URL·PDF 쪽/인쇄 쪽, 개념 ID, 정답표/해설 위치를 연결한다. 로컬 `source_id`는 반드시 같은 manifest의 `sources`에서 해석한다. 과목마다 반복되는 `P01` 같은 값은 전역 문항 ID가 아니다. 없는 연도·식별자를 추측해 채우거나 원래 ID를 새 형식으로 바꾸지 않는다.
3. **집계와 노출을 검증한다.** 등록 수를 실제 `questions` 길이·고유 문항 ID 수·승인된 분량과 대조하고, 시간 합과 AI 문항 수를 계산해 기준 충족 여부를 확인한다. 문항 수와 하위 응답 칸 수를 구분한다. 미선정 과목은 미등록으로 두고 원장 전체 완성을 주장하지 않는다. 원장에는 정답 근거의 위치를 연결하되 정답값을 불필요하게 복제하지 않아 독립 풀이의 답 노출을 막는다. manifest에 적힌 해시는 기록된 값으로 표시하고 현재 파일을 새로 검증한 값과 구분한다.
4. **기존 원장에 병합하고 정확한 대상을 재조회한다.** 완료 카드라면 기존 결과·요약·메타데이터를 보존하는 2절의 `edit --result --summary --metadata` 절차를 사용한다. 다른 과목·과거 사이클을 덮어쓰지 않도록 같은 과목·사이클·문항의 중복 등록을 검사한다. 현재 문항 유지가 조건이면 원본/현재 자료를 수정하지 않고, 필요한 경우 등록 전후 manifest·PDF의 `sha256sum`을 비교한다. 기록한 원장·승인 상태·과목별 수와 미등록 범위를 읽어 확인한다.
5. **새 사이클의 후보를 과거 전체 사용 목록과 대조한다.** 선정자는 원래 문항 ID와 발행 자료/문항코드뿐 아니라 원문 내용·재수록 관계도 확인한다. 파일명·미러·책형·코드·이미지 해시가 다르다는 사실만으로 비중복을 확정하지 않는다. 독립 검수자는 과거 목록·새 목록·식별 근거를 별도로 대조하고 결과·담당·판본을 해당 제작/검수 카드와 원장에 남긴다. 실제 대조 전의 빈 검사 기록을 중복 0개로 표현하지 않는다.
6. **부족과 충돌은 해당 교체의 중지 조건으로 처리한다.** 적합한 다른 원문을 확보하지 못했거나 동일 문항 여부가 불명확하면 필요한 개념·필요/확보 수·조사 범위·막힌 이유를 기록하고 총괄이 즉시 사용자에게 보고한다. 이전 문항 재사용·AI 생성/변형·90분 임의 변경으로 해결하지 않는다. 기존 계획과 충돌하는 선정은 실행 전에 사용자 결정을 받는다. 승인된 다른 독립 작업까지 일괄 중단하지 않는다.
7. **등록과 실행을 분리해 짧게 보고한다.** 기록한 카드/원장·후속 지시, 현재 문항 유지 여부, 실제 등록 과목/문항 수와 미등록 범위, 다음 사이클 후보 대조의 실행 여부를 알린다. 원장·검사 절차를 기록한 것만으로 자동 중복 차단기나 다음 사이클 자료 제작을 구현했다고 주장하지 않는다.

## 7. 미수정 보존·보관 취소로 범위를 바꿔 종료한다

1. 최신 요청이 남은 수정 회차를 철회한 것인지, 업로드만 취소한 것인지, 비교 보고만 요구한 것인지 구분한다. 관련 카드의 현재 상태·run·확정 판정·실파일을 읽고, 이전에 허용된 수정·재확인·출판을 계속할 권한이 있다고 가정하지 않는다.
2. **출판·업로드 취소부터 처리한다.** 선행 보고 카드를 닫으면 자식 출판이 실행될 수 있다. 미실행 보관 카드는 취소 사유를 기록하고 `hermes kanban --board ksat-10000 archive <카드ID>`처럼 지원되는 취소 보관 경로로 비활성화한 뒤 상태·실행 이력을 다시 읽는다. `--rm`으로 이력을 지우거나 업로드 성공으로 `complete`하지 않는다. 이미 실행 중이면 승인된 중지 경로로 정확한 실행만 멈추고 완료된 전송·미완료 범위를 구분한다. 취소됐다는 이유로 원격 파일을 임의 삭제하지 않는다.
3. **최초 판본과 판정을 그대로 보존한다.** 원고·PDF·빌드·검수 파일을 고치거나 새 수정 작업자를 만들지 않는다. 실제 입력 해시나 같은 범위의 폴더 확인값을 보고 전후 대조하고, 미해소 지적·수정 사용 횟수·재확인 미실시·품질 불통과·미인수를 유지한다. 수정 0회는 권한 소진과 다르며, 현재 수정을 하지 않는 이유는 사용자 지시로 기록한다.
4. 실제 비교 보고에는 결함의 위치·종류·영향과 각 판본의 상태를 포함한다. 조판 결함을 정답 오류로, 내용 대조 통과를 판본 전체 통과로 바꾸지 않는다. iCloud는 확인된 보관·사용자 진술·예정·대기·취소를 구분하고, 작업 실행 이력이 없다는 사실만으로 원격 경로 자체가 존재하지 않는다고 단정하지 않는다.
5. 비교·정리 카드의 제목·본문·최신 요약·결과·메타데이터를 새 범위에 맞추고 원래 지적과 승인 이력은 보존한다. 사용자에게 실제 보고한 뒤 필요한 보고 업무만 종료하며, 이를 자료 수리나 품질 인수로 표현하지 않는다. 중앙 피드백 인계점에도 취소와 보존 결론을 남긴다. 수동 종료·무재실행 검증은 5절을 따른다.

## 8. 수정필요 판정의 후속 배정과 진행 브리핑

1. 최신 수정 허가·확정 판정·현재 쓰기 영역과 한도를 확인한다. 작성 중인 진행 메모와 최종 판정을 구분하고, 완료 카드의 댓글을 실제 수정 배정으로 대신하지 않는다. 총괄의 관리 도구를 먼저 확인해 기능 부족을 파일 제작자나 제한된 작업자에게 떠넘기지 않는다.
2. 수정 한도의 적용 단위와 이미 쓴 회차를 먼저 확인한다. 전체 산출물에 한 번 허용된 수정을 분할 카드마다 한 번씩 복제하지 않는다. 변경 전 PDF·원고·판정·봉인 근거를 보존하게 하고 지적 ID·정확한 위치·허용 수정 파일·비변경 범위·새 판본/인계·검증 기준을 수정 전용 카드에 쓴다. 원판 보존이 조건이면 수정판과 새 원장·검사·변경 기록을 별도 쓰기 구역에 배정한다. 후속 인수용 입력 매핑에 각 문서·원장의 현행 경로·판본·해시와 원판 참조를 명시하게 해 수정판과 미변경 원판이 조용히 섞이지 않게 한다. 기존 고정 원장이 읽기 전용이면 그 원장을 덮어쓰는 권한으로 확대하지 말고 대응 수정판과 실제 배포 CSV/표의 허용 행·필드를 함께 지정한다. 검수표의 `target_path`는 결함이 발견된 원위치이지 쓰기 허가가 아니므로, 원위치와 실제 허용 수정 경로를 별도 열로 대응시킨다. 승인 범위 안의 새 파생 보정본으로 해결할 때는 원값·수정값·원본 쪽·해시·영향 ID와 실제 소비 포인터 갱신까지 지정한다. 보정 사본만 만들고 연결표가 계속 옛 원장을 가리키면 사용자에게 전달되는 결함은 고쳐지지 않는다. 필요한 쓰기 범위가 기존 승인 밖이면 해당 필드만 대기시키고 실행 전에 총괄에게 반환한다. `create --initial-status blocked --idempotency-key <수정회차키>`로 준비하고 같은 회차의 카드가 있으면 소유자·진행을 확인해 재사용한다. 뒤 분할의 확정 필수 결함은 그 승인 회차에 누적하되 권고·근거 있는 보류·새 사용자 결정이 필요한 범위와 구분한다.
3. 공유 입력의 판본과 남은 최초 분할을 확인해 `관련 최초 분할 → 승인 회차의 수정 카드 → 같은 검수자의 재확인·전체 대사`로 연결한다. 지원되는 CLI에서는 `link <최초분할카드> <수정카드>`와 `link <수정카드> <재확인카드>`로 선행을 등록하고 부모 집합·상태·실행 이력을 읽어 확인한다. 수정 전 고정 판본을 읽는 분할이 남았고 별도 불변 입력도 확보하지 않았다면, 수정 카드는 등록해 두되 그 분할들이 끝날 때까지 운영 대기로 유지한다. 현재 Wiki나 원본 manifest를 먼저 바꾸면 뒤 분할의 해시·판정 기준이 달라지기 때문이다. 기존 미실행 재확인·전체 대사 카드가 같은 검수 담당과 승인 계약을 충족하면 수정 카드를 그 부모로 추가해 재사용할 수 있다. 최초 판정·봉인 풀이를 보존하고, 첫 판정을 소급 통과로 바꾸거나 완료된 최초 검수 카드로 역방향 의존성을 만들어 순환을 일으키지 않는다. 최초 검수가 수정 필요이면 새 재확인을 인수 카드의 미완료 선행으로도 연결해 통과 전 인수가 열리지 않게 한다. 사용자 대면 총괄의 수동 인수·보고 카드에는 작업자를 띄우지 않으며, 완료를 준비한다는 이유로 그 카드를 먼저 `unblock`하지 않는다.
4. 후속 출판의 부모를 바꿔야 하면 새 미완료 인수 부모를 먼저 `link`하고 확인한 뒤 옛 부모를 `unlink`한다. 연결을 바꾸는 중 출판이 먼저 실행되지 않게 하고, 실제 판정·인수와 승인 PDF 확인값을 별도 게이트로 둔다. 해당 운영 기능이 없으면 불완전한 경로를 실행하지 말고 사용자 대면 총괄에 인계한다.
5. 마지막 최초 분할이 끝나면 `show --json`의 부모 ID 집합과 `list --json`의 현재 상태를 조인해 예상 부모 수·실제 조회 수·미완료 목록을 대사한다. 이어 실행 원장의 카드·run·manifest별 인수 기록을 대조해 `done`이지만 아직 미인수인 제출물을 먼저 확인한다. 이미 인수한 같은 바이트의 결과는 다시 검수하거나 완료 수에 더하지 않는다. 기존 수정 카드의 최신 입력·정확한 수정 파일/필드·원판 보존·비목표를 갱신하고, 첫 시작 명령에 사용량·겹침·동시성 대사와 구독 등록·실행 댓글·활성화를 묶고 배정 한 줄을 남긴다. 다음 show로 running과 run 번호를 한 번 확인하며 구독·작업자 세션 DB·응답·도구 활동을 다시 보지 않는다. 수정 뒤에는 새 확인값과 실제 변경·영향 범위를 같은 검수자가 확인하며 불필요한 전면 감사·추가 검수자를 늘리지 않는다.
6. 같은 차단이나 `block_loop_detected`가 반복되면 실제 상태·차단 종류·미충족 입력·새 run을 대조하고 재실행 루프를 중단한다. 명령 성공만으로 `blocked` 유지나 무재실행을 가정하지 않는다. 낭비 실행은 실제 작업자 run으로 세고, 차단 재발 횟수·수동 종료 기록과 구분한다.
7. 진행 조회는 한 번의 기준시각과 대상 목록을 고정해 현재 run·최근 근거·판정·후속 배정 공백만 확인한다. ETA는 실제 남은 경로와 처리 기록으로 조건부 계산하고 수정·재확인·배정 대기를 포함한다. 작업자의 견적, 최근 실측을 사용한 계산, 총괄의 가설을 구분한다. 기준시각에 임의의 분 수를 더하고 반올림한 시각만으로 정밀한 예상 종료를 만들지 않는다. 근거가 부족하면 미정으로 남기며 새 차단으로 전제가 깨졌으면 과거 예상을 먼저 철회한다. 시작 확인을 완료 대기 폴링으로 늘리지 않는다.

## 9. 학습 PDF 우선 전달·정확 판본 컨펌·참고판 전환

1. **현재 게이트부터 읽는다.** 제작 카드의 현재 run·정확한 판본·출력 목록과 최신 사용자 결정을 묶어 확인한다. 제작 완료, 검토용 전송, 그 판의 OK, AI 최종 오류 검사, 총괄 인수, 사용자 최종 품질 승인, 실제 학습을 서로 다른 상태로 둔다. 사용자 메시지가 다른 판본이나 디자인 후보에 관한 것이라면 학습 PDF의 OK로 사용하지 않는다.
2. **선택된 정확한 PDF부터 대사해 먼저 전달한다.** 먼저 제작자가 제공한 최종 납품 선택표(예: `최종납품선택.json`)와 handoff의 실제 스키마를 읽어 첨부 대상의 절대경로·빌드·판본·쪽수·크기·SHA256 집합을 고정한다. 같은 실행 폴더에 동명 중간 PDF가 남아 있을 수 있으므로 basename·폴더 위치·최신 시각만으로 최종본을 고르지 않는다. 선택된 파일에만 `test -f`, `stat`, `sha256sum`, `pdfinfo` 등 무쓰기 조회를 적용하고 선택표·handoff와 대사한 뒤 먼저 첨부한다. 필요하면 첫 쪽의 검수 전 표기와 실제 인쇄 판본문구만 읽는다. 제출 명세의 빌드 식별자와 PDF 인쇄 문구를 구분하고, 읽지 않은 전체 빌드명이 PDF에도 인쇄됐다고 주장하지 않는다. 전체 원고·모든 입력 재해시·전 쪽 재렌더·내용 검수를 먼저 복제해 첨부를 늦추지 않는다. 제작자의 자동 검사·전 쪽 렌더·원문 화소 대사 실적은 제작자 보고로 명시한다.
3. **정확한 파일과 캡션을 함께 고정한다.** 승인된 목적지에 검수 전·마스터 컨펌 대기, 판본, 일차별 학습지/해설, 실제 쪽수, 제작자가 반영한 변경점 몇 줄을 적는다. 총괄의 확인을 의미 검수나 품질 통과로 표현하지 않는다. 최종 본문·각 파일 캡션에서 불필요한 제어문자를 검사하고, 같은 basename의 여러 일차 파일은 캡션으로 구별한다. 원본 시험지·독립 원문 이미지·검수 기록·외부 미리보기 캡처는 첨부 대상에서 제외한다.
4. **전송 경로와 메시지 묶음의 읽기 검증을 분리한다.** 직접 API를 사용할 때는 알림 억제가 없는 명시적 필드를 적용한다. CLI를 사용할 때는 현재 `hermes send --help`를 먼저 확인한다. 텍스트 파일을 읽는 `--file`을 PDF 첨부 옵션으로 쓰지 말고, 지원되는 경로에서는 `hermes send --to "discord:$channel_id" --json "${caption}\nMEDIA:${absolute_pdf_path}"` 형태로 명시적 대상과 미디어 지시를 전달한다. 이 예시의 `\n`은 실제 줄바꿈으로 구성한다. 여러 파일은 선택된 각 절대경로의 `MEDIA:` 지시를 서로 다른 줄에 모아 한 번에 전송할 수 있다. 전송 전 채널의 최근 메시지 기준점을 보관하고, 전송 후 반환 ID와 그 기준점 이후의 한정 조회를 함께 사용해 캡션과 요청한 모든 파일 메시지를 찾는다. 캡션과 첨부가 별도 메시지로 나뉠 수 있으므로 반환 ID 하나나 본문 없는 첨부 메시지를 전체 전달의 실패·성공으로 단정하지 않는다. 대상·작성자·캡션·각 메시지의 첨부명/크기를 로컬 선택표에 대응시키고, 요청 파일 집합과 실제 확인 집합을 대사한다. 전송 응답이 누락되거나 모호해도 먼저 이 게시 상태를 확인하고 같은 파일을 재전송하지 않는다. 수신측 파일명이 인코딩·변환될 수 있으므로 원래 이름이 그대로 게시됐다고 가정하지 않는다. 메시지/첨부 메타데이터 확인과 CDN 전체 바이트 재해시는 다른 검증이다. 조회 응답에 알림 플래그가 없으면 미확인으로 남기고, 플래그 검증이나 휴대폰 푸시까지 확인했다고 하지 않는다. 선택 검사를 채우려고 비밀값 탐색·설정 변경·다른 프로필 인증 사용으로 확대하지 않는다.
5. **전송 결과를 보존 병합한다.** 제작 카드의 기존 결과·요약·메타데이터를 읽어 보존한 뒤 정확한 판본·일차/종류별 메시지 ID·로컬 경로/확인값·실제로 읽기 검증한 범위·미확인 범위·다음 책임자를 병합한다. 최초 제작 요약은 처음 갱신할 때 별도 필드에 고정하고, 재진입에서는 그 보존값을 인수 요약으로 덮어쓰지 않는다. 제작자가 남긴 ‘직접 전송하지 않음’ 같은 필드는 당시 행위자의 사실로 유지하고, 총괄의 실제 게시·읽기 검증은 `administrator_delivery` 같은 별도 객체에 기록한다. 한쪽의 과거 false를 다른 행위자의 현재 실패로 해석하거나 총괄의 게시를 제작자의 실적으로 소급하지 않는다. 번호 선택·수정 견본 OK·전체 학습판 OK도 서로 다른 필드로 유지한다. 현재 결과가 실제 첨부 완료를 반영하되 사용자 OK·AI 검사·품질 인수는 각각 실제 값으로 유지되는지 재조회한다. 이미 검증해 첨부한 파일은 최종 응답에서 게시물 링크로 안내하고, 새 `MEDIA:` 지시로 중복 첨부하지 않는다. 전송 결과가 모호하면 같은 파일을 재전송하지 말고 정확한 메시지부터 확인한다.
6. **미컨펌 참고판은 현재 승인 대기에서 뺀다.** 사용자가 해당 판을 확인하지 않고 다음 디자인판으로 넘어가도록 정하면 카드의 제목·현재 결과·요약·참고 표지·컨펌 대기 여부·AI 검사 허용 여부·다음 책임자를 함께 바꾼다. 원래 제작 요약·전송 이력·이전 게이트는 이력으로 보존하고 파일·원고·manifest와 인쇄된 역사적 판본은 고치지 않는다. 참고용 표지를 붙인다고 최종판 버전이나 품질 통과가 되는 것은 아니다. 그 판의 OK를 다시 요청하거나 AI 검사를 자동 배정하지 않는다.
7. **새판의 변경 계약을 따로 고정한다.** 디자인 전용 재제작이면 승인된 내용·문항·정답/해설·시간·수행 순서·복기/번호 연결을 고정하고 같은 제작자가 새 쓰기 영역에서 디자인만 이관한다. 실제로 접수한 피드백만 추가하며 없는 피드백을 추정하지 않는다. 사용자 피드백 반영 회차와 AI 오류 검사 뒤 한정 수정 회차를 별도로 기록한다. 같은 사이클의 판본 교체를 새 문항 사용으로 중복 등록하지 않는다.
8. **새 정확 판본의 OK 뒤에만 최종 검사한다.** 새판도 제작자 자체 점검 뒤 먼저 첨부하고 그 판의 OK를 기록한다. AI 검사에서는 이미 선택된 디자인·구성·분량을 재설계하지 않고 승인된 사실 오류·가독성 범위를 본다. 오류 수정과 같은 검수자의 변경부 재확인 한도는 해당 승인 단위를 따른다. 확인 대기를 다른 독립 작업 전체에 걸지 않되, 공통 양식의 사용자 선택·반영이 모든 후속 과목의 필수 조건이면 그 조건은 실제 제작 부모/운영 게이트로 유지한다.
