# 학습자료의 모델·판본 비교

## 적용 범위

승인된 모델·설계로 학습자료를 별도 제작하거나 기존 판본의 장점을 취합해 개선할 때, 또는 기존 카드의 담당·모델을 실행 없이 정리할 때 읽는다. 같은 모델의 여러 판본과 서로 다른 모델의 비교를 구분한다. 사용자 선호와 승인 경계는 SKILL.md를 적용하고, 모델 고정·실제 실행·사용량은 `hermes-agent`의 `references/background-systems.md`와 `references/providers-and-models.md`를 따른다. 절차 등록·착수를 산출물·검수·비교 완료로 표현하지 않는다.

## 1. 승인과 비교 조건을 한 번에 고정한다

1. 기준 제작/검수 카드와 판본, 승인된 제작·검수 모델/공급자, 쓰기 경로, 수정 한도, 실제 보고 담당과 완료 조건을 읽는다. 프로필 기본값 변경과 작업별 모델 예외를 구분한다. 사용자가 모델 식별자를 지정했으면 그대로 사용하고 임의 별칭으로 바꾸지 않는다.
2. 카드 시작은 SKILL.md 3절 맨 앞의 두 명령으로 끝낸다. 첫 명령에 사용량·겹침 대사·생성·구독·실행 댓글·unblock을 묶고 다음 show로 running과 run 번호를 한 번 본다. 정상 경로의 도움말·모델/fallback·구독·예약·기준 문서를 카드마다 재조회하지 않는다. 인증값을 직접 읽거나 다시 제출하게 하지 않는다.
3. 기준판의 `source-manifest.json`과 구조화 메타데이터에서 원문 ID·순서·쪽/좌표·정답 근거·개념 범위·복기 항목·시간 배정을 잠근다. **독립적인 동일 조건 제작인지, 기존 설명·검수·디자인을 참고하는 취합 개선인지** 입력 계약을 먼저 구분한다. 전자는 불필요한 기준판 설명·정답 노출을 막고, 후자는 사용자가 승인한 참고를 허용하되 무엇을 읽고 재사용했는지 기록한다. 개선 실험을 완전 독립 생성이나 모델 자체의 공정한 성능 시험으로 표현하지 않는다.
4. 기준 PDF·manifest·handoff의 판본과 내용 보존 범위는 인계에서 식별한다. 통상 인수의 파일·입력 SHA256·모델 확인은 tools/accept_check.py 한 번으로 끝내며 프로필 설정 해시·폴더 스트림 해시를 시작 조건으로 추가하지 않는다. 도구의 일치는 내용 품질 승인이 아니다.

## 2. 별도 제작·독립 검수·실제 비교 보고를 배정한다

1. 산출물 종류와 최신 승인에 맞춰 네이티브 카드의 흐름을 먼저 고정한다. 일반적인 위키·검수 계약은 제작 → 독립 검수 → 총괄 비교 보고를 따르되, 마스터 선확인 대상 학습 PDF는 제작자 자체 점검 → 우선 첨부·정확 판본 OK → AI 최종 오류 검사로 연결한다. 디자인 견본의 입력 계약과 승인 방식은 먼저 7절에서 구분한다. 번호 후보 선택과 조사 근거 전용 새 양식 컨펌을 같은 절차로 강제하지 말고, 어느 경우에도 견본 제작 앞에 학습 PDF의 AI 최종 검수를 끼워 넣지 않는다. 준비 중에는 초기 `blocked`와 산출물별 중복 방지 키를 사용하고 첫 명령에 단일 담당 봇 구독·실행 댓글·쓰기 경계 대사·해제를 묶고 배정 한 줄을 남긴다. 구독을 별도로 재조회하지 않는다. 준비용 차단을 사용자 승인 거부로 보고하지 않는다.
2. 승인된 모델·공급자를 해당 카드에 고정하는 명령 형태는 다음과 같다. 제작과 검수의 지정값은 각각 확인하고, 실제 플래그는 설치된 `create --help`와 대조한다.

```bash
hermes kanban --board ksat-10000 create "$title" \
  --body "$body" --assignee ksat-author \
  --workspace "dir:$project_root" --tenant "$tenant" \
  --idempotency-key "$variant_key" --initial-status blocked \
  --model "$approved_model" --provider "$approved_provider" \
  --completion-contract local-only --json
```

3. 검수는 승인된 검수 모델을 유지한다. 제작 모델이 다르다는 이유로 검수 모델을 복제·변경하지 않고, 사용자가 제작·검수에 같은 모델을 지정했으면 그대로 고정해 동일 모델이라는 한계를 보고한다. 지원되는 카드별 재시도 제한으로 불필요한 재실행을 막되 전역 보호·fallback 설정은 바꾸지 않는다.
4. 수정필요 판정과 **현재도 유효한** 수정 승인이 함께 있을 때만 같은 제작자·모델의 수정 전용 카드를 사용자 대면 총괄이 배정한다. 원래 검수의 상태·완료 계약에 맞춰 같은 검수자의 재확인을 연결한다. 판정 인계 계약으로 첫 회차가 이미 종료됐으면 별도 재확인 카드에 최초 판정을 승계할 수 있으나, 완료된 부모를 역방향으로 다시 연결해 순환을 만들지 않는다. 작업자에게 구독·부모 교체·활성화 기능이 있는지 추측해 전체 제어를 넘기지 않는다.
5. 총괄 비교는 추가 제작·전면 감사가 아니다. 읽기 전용으로 기존 검수와 실제 파일을 대조하고 문안 인계와 실제 사용자 전달을 구분한다. 칸반 총괄이 문안만 맡는 계약이면 댓글에 남기고, 실제 보고는 사용자 대면 총괄이 요청된 시점에 한다. 미수정 보존·업로드 취소를 지시받으면 `learning-material-feedback.md` 7절로 전환하고, 이전 수정·출판 흐름을 계속하지 않는다.

## 3. 처음부터 새로 제작했는지와 실제 모델을 확인한다

1. 먼저 입력 계약의 독립 제작·취합 개선·내용 보존 디자인 재설계를 구분한다. 내용 보존 재설계에서는 승인된 설명·문항·도식 내용·원문 자산을 유지할 수 있어도 기존 시각 스타일의 재사용까지 허용된 것은 아니다. 새 디자인 근거의 허용 목록을 별도로 고정해 내용 재사용과 시각 설계 재사용을 혼동하지 않는다. 독립 제작이면 새 폴더에 원고·생성 스크립트·조판·PDF를 처음부터 작성하고 기존 모델의 원고·빌드·조판·PDF·추출 자산을 복사해 고치는 방식으로 대체하지 않는다. 취합 개선이면 승인된 참고·재사용 범위 안의 원고·스타일·자산만 사용하고 선택한 부분과 계보를 기록한다. 독립 제작의 복사 금지를 취합 개선에 일괄 적용하거나, 취합 허가를 전체 코드·자산 복제 허가로 확대하지 않는다. 원문 문항은 해당 계약이 지정한 공식 원본·좌표·재사용 조건을 따르고 원문·선지·조건을 변형하지 않는다.
2. 문항 수·순서·개념 범위·시간 배정·복기 번호는 잠근 명세와 대조한다. 비교를 이유로 새 문항·새 범위·설명에 필요한 조건 누락을 허용하지 않는다. 같은 사이클 비교 판본은 기존 문항 원장의 참조로 연결하고 새 사이클/새 고유 문항으로 세지 않는다.
3. 시작 다음 명령의 show에서 running과 run 번호를 한 번 확인한다. 실제 모델·공급자 확인은 인수 때 /usr/bin/python3 -B tools/accept_check.py <카드 ID>로 갈음한다. '판정: 일치'면 세션 DB·API 응답·도구 활동을 따로 확인하지 않으며, 불일치·검사 불가일 때만 그 줄이 지적한 부분을 직접 본다.
4. 전 쪽 PDF 렌더·수식/근호/지수·폰트·원문 완전성·공식 정답 근거·계산·번호 연결을 기존 승인된 기준으로 검사하고 자체 점검과 독립 검수를 나눈다. 디자인 견본에서는 실제로 삽입·검증한 원문 영역과 비워 둔 자리를 구별하고, 미삽입 영역의 원문 무손실 검증을 완료로 세지 않는다. 디자인 견본의 제작·검수와 실제 일차별 학습지·해설의 제작·검수를 별도 완료 조건으로 둔다. 처음부터 작성했다는 담당의 말만으로 파일 보존이나 요구 충족을 확정하지 않는다.

## 4. 최초 검수와 비교 근거를 보존한다

1. 검수자는 제작에 참여하지 않은 세션에서 실제 수행·열람 범위를 기록한다. 블라인드 첫 풀이가 승인된 대상에만 묶음 전체의 첫 판단을 정답·해설 열람 전에 봉인하는 절차를 적용한다. 공식 기출·EBS에 정정 조사·기계 대조·예외 원문 확인·새 해설/개념 연결 검수를 적용하도록 승인돼 있으면 그 방식으로 대조하고, 모델 비교를 이유로 새 정답 선택·선지 타당성 재판정을 추가하지 않는다. AI 제작 문항 등 별도 검증이 필요한 대상의 절차는 그대로 유지한다. 같은 문항을 이미 검수했거나 정답이 노출됐다면 새 독립 첫 일치와 재확인을 구별하며 완전한 초견 시험으로 표현하지 않는다. 비교 원장에는 정답값 대신 정답 근거 위치를 연결한다. 블라인드 대상의 현재 ID 선필터링·부수 노출·후속 카드의 답 없는 ID 인계는 `source-grounded-wiki.md`의 ‘독립 첫 풀이를 묶음 봉인하고 정답 노출을 인계한다’를 따른다.
2. 첫 제출 PDF·원고·handoff와 첫 검수 report/verdict를 수정 전에 보존한다. 지적마다 고유 ID·중대도/유형·쪽·근거·요구 수정을 남기고 최초 지적 수와 수정 후 잔여 지적 수를 분리한다. 판본 한계·미검증 사항을 결함 수에 섞거나 수정 후 기록으로 최초 지적을 지우지 않는다.
3. 요청된 모든 판본에 같은 품질 축을 적용한다. 읽기 쉬움·내용 정확성·복기 연결·수식 가독성과 색·상자·여백 같은 디자인 차이를 나눠 실제 쪽과 근거로 비교한다. 가능하면 같은 렌더 조건을 쓰되, 읽기 전용 보존 작업에서는 기존 렌더의 DPI·색 공간 차이를 명시하고 픽셀 크기를 정량적인 글자 크기 비교로 삼지 않는다. 크기 수치를 보고할 때는 조판의 `font-size`, 변환의 가로/세로 배율, 줄 간격, PDF 쪽·병치 영역의 실제 크기를 나누어 확인한다. 가로 늘이기는 글자 폭의 변화로 설명하고, 균등한 글자 확대나 pt 증가로 바꾸어 보고하지 않는다. 잘림이 의심되는 확대 이미지는 먼저 원래 전체 쪽에서 같은 위치를 확인한다. 고정된 확대 영역의 경계가 본문을 자른 것을 실제 PDF의 잘림으로 오판할 수 있기 때문이다. 자동 검사 통과 수·쪽수·색 대비·페이지 밖 이탈 0은 내부 글리프 겹침이 없다는 증명이 아니다. 근호 차수·지수·아래첨자는 실제 확대 렌더로 판독하고, 총괄 표본과 독립 검수의 전 쪽 범위를 구분한다.
4. 공통 개념을 고르고 각 PDF의 실제 문단을 판본·쪽과 함께 그대로 발췌한다. 문단을 새로 쓰거나 길이를 억지로 맞추지 않고, 뒤의 표·정의·예시가 빠진 발췌라는 한계를 밝힌다. 대표 개념 쪽과 결함 확대의 실제 로컬 경로를 대응시키며 첨부 허가로 확대하지 않는다. 사용자 이해도·학습 효과를 측정하지 않았다면 총괄의 사용성 판단과 분리한다.

## 5. 시간·사용량과 사용자용 결과를 대조한다

1. 제작·검수·조건부 수정의 각 현재 run에서 실제 시작/종료를 읽고 도구로 경과 시간을 계산한다. 카드 준비·배정 대기·회차 실행·저장 세션 종료를 한 시간으로 섞지 않는다. 실행 중 값은 중간 관측이라고 표시한다.
2. 사용자가 작업별 시간·토큰 비교를 따로 요청한 경우에만 해당 지표를 읽고, 실제 저장 세션의 입력/출력·캐시·추론 토큰·호출 수와 계정 사용 창을 구분한다. 통상 시작·인수에 이 추가 조회를 적용하지 않는다. 공급자별 집계 정의가 다르면 무리한 합계나 비율을 만들지 않는다. 계정 사용률 차이를 해당 작업만의 사용량으로, 포함 구독의 추정 비용 0이나 실제 비용 `null`을 실제 청구 0으로 바꾸지 않는다. 확인할 수 없는 값은 미확인이다.
3. 모든 비교 판본의 학습지·해설 절대경로·판본·쪽수, 요청된 개인 보관 경로와 실제 확인 상태, 최초 지적의 개수·내용·수정 횟수·재확인, 네 품질 축, 실제 문단·쪽·대표 렌더 경로, 단계별 시간·사용량, 총괄 의견·근거·한계를 전달한다. 미해소 지적은 그대로 드러내고 내용 검증 통과·조판 결함·전체 품질 불통과를 구별한다. Discord에서는 표 대신 판본별 항목을 대응시키며, 경로 안내를 파일 첨부·업로드 허가로 해석하지 않는다.
4. 실제 게시가 완료 조건이면 지정 경로에 전달하고 정확한 반환 메시지 ID를 읽어 전체 내용·대상·작성자·첨부·알림 플래그를 확인한다. 보고가 여러 메시지로 나뉘면 모든 부분의 ID와 검증을 남긴다. 전송이 막히면 승인 우회나 문안만의 완료 처리 대신 차단을 보고한다.
5. 총괄 의견과 사용자 최종 품질 승인을 분리한다. 단일 과목·단일 범위의 비교 결과를 모델의 보편적 우열로 확대하지 않는다. 실제 파일·검수·사용량·게시 근거가 없는 결과는 채워 넣지 않는다.

## 6. 승인된 대체 모델 판정을 짧게 보강한다

1. 승인된 계획이 대체 모델의 실제 판정 뒤 다른 모델의 짧은 보강을 요구하는지 확인한다. 단순히 모델을 임시 지정했을 뿐 아직 판정하지 않은 작업에는 보강 카드를 미리 실행하지 않는다. 짧은 보강, 수정본의 같은 모델 재확인, 과목 전체 최종판정을 구분해 중복 검수와 수정 회차 확대를 막는다.
2. 보드에서 같은 범위의 기존 보강 카드와 중복 방지 키를 먼저 찾는다. 새 카드가 필요하면 승인된 단계 한 장으로만 등록하고 대상 판정·고정 ID 목록·선정 이유·실제 검사 수·미검사 모집단을 명시한다. 적합·수정 후보·부분·보류 경계를 확인하는 표본을 전수 검수처럼 보고하지 않는다.
3. 제작 수정과 병행하려면 보강 입력을 원래 판정 보고서·개념 정의 발췌·공식 근거·manifest가 고정된 스냅샷으로 한정한다. 변경 중인 현행 Wiki나 수정 run은 읽기에서도 제외한다. 필요한 정의가 스냅샷에 없으면 확인 한계를 남기고 최신 원고를 대신 읽지 않는다. 쓰기 폴더만 분리하면 입력 판본의 경쟁 상태가 남기 때문이다.
4. 승인된 복구·계측 확인 절차와 공급자별 슬롯을 충족한 뒤 지정 모델로 실행한다. 기존 판정과 보강 판단을 ID별로 병기하고 근거 충돌·범위 한정·미확인을 구분한다. 해당 작업에서 금지한 새 풀이·정답 선택·선지 재판정이나 새 집필은 하지 않는다.
5. 표본 ID의 누락·초과·중복과 보강 근거를 검증하고 총괄에게 인계한다. 보강이 끝나기 전에도 다음 단계 진행을 허용한 승인이라면 임의의 강제 선행을 추가하지 말고 대기·한계를 인수 보고에 표시한다. 이 허용으로 기존 필수 결함·실제 수정본 재확인·사용자 품질 승인까지 건너뛰지 않는다.

## 7. 공개 대표 교재 조사에서 승인용 디자인 견본으로 잇는다

1. **조사 계약과 소비 게이트를 먼저 정한다.** 최신 승인에서 우선 교재군, 과목별 강사/교재 목표, 현재 실행 유지 여부, 완료·인수 순서, 로컬 보관 범위와 견본 착수 조건을 읽는다. 기존 양식의 번호 후보를 고르는 계약이면 8번, 조사만 근거로 새 양식을 컨펌하는 계약이면 9번 절차를 적용한다. 새 지시가 옛 후보 선택을 대체하면 기존 카드의 현재 제목·본문·결과·요약·선택 상태와 다음 책임자를 맞추고, 원장과 같은 카드에 대체 사유를 기록해 읽어 확인한다. 과거 추천은 당시 이력으로 보존하고 현재 승인으로 사용하지 않는다. 후보 요청의 종료를 후보 채택·품질 통과·새 양식 컨펌으로 바꾸지 않는다. 기존 일반 개념서 조사는 보조 비교로 보존하고 새 우선 근거와 섞어 충족으로 세지 않는다. 추가 조사가 필수이면 해당 카드를 후보의 실제 부모로 연결하고 `show --json`에서 부모 집합·`blocked`·실행 이력 부재를 확인한다. 기존 조사 하나가 끝났다고 먼저 후보를 시작하지 않는다. 이미 진행 중인 작업의 범위를 유지해야 하면 확인된 결과를 승계하고 새 기준의 부족분만 승인된 후속에서 다룬다.
2. **대표 강사와 대표 개념 교재를 각각 근거로 선정한다.** 인강 사이트의 정상 공개 대표 표시·수강생 수·판매 순위·공식 커리큘럼을 실제로 읽는다. 근거 장부에 과목, 강사, 플랫폼, 지표/표시 원문, 기간·누적 여부·판매 범주, 출처 URL, 열람 시각, 선정 이유와 한계를 남긴다. 단순 노출 순서를 순위로, 플랫폼 홍보를 전국 절대 순위로, 인기 지표를 수업 효과로 바꾸지 않는다. 사용자 예시는 검색 후보이지 확정 명단이 아니다. 강사를 선정한 근거와 해당 책이 대표 개념 교재라는 근거를 별도로 연결하고, 통합 과목과 특정 세부 과목 전용 교재·구판과 현행판을 구분한다. 관찰 교재가 통합 과목이라는 사실만으로 강사의 세부 과목 매출 지표가 통합 과목 순위로 바뀌지는 않는다. 세부 과목 지표·강사 전체 누적 수강생 수를 쓰면 대상 과목과의 범주 차이를 선정 장부와 사용자 보고에 함께 표시하고, 추가 근거가 필요한 범위만 후속에 남긴다.
3. **교재별 접근 상태를 먼저 분류한다.** 로그인·결제·수강생 전용은 열지 않고 실제 경계 표시를 근거로 비공개 제외를 기록한다. 공개 미리보기 미발견, 도구/네트워크/HTTP 오류, 표지·목차만 공개, 본문 표본 확인을 서로 다른 상태로 남긴다. 추출 도구의 기능·설정 오류는 사이트의 비공개 증거가 아니다. 정상 공개 브라우저 등 허용된 읽기 경로를 쓰되 사이트 접근 차단·미리보기 범위를 우회하거나 자격증명을 새로 찾지 않는다. 공식 페이지/UI가 실제 제공한 링크만 추적하고 숨은 원본 URL·문서 ID를 추측하지 않는다.
4. **보이는 본문을 실제로 확인한다.** 정상 뷰어의 이동·로딩 완료 뒤 화면을 읽고, 표시된 입력값·요청한 순번·실제로 열린 본문을 구분한다. 쪽 번호 입력이나 클릭이 성공했다는 이유만으로 목표 쪽을 읽었다고 세지 않는다. 표지·목차·뒤표지·로딩 화면·전환 중 겹친 화면은 본문 표본에서 제외한다. 뷰어 순번과 인쇄 쪽을 기록하고 작은 글자/표/도식은 필요한 영역을 확대한다. 쪽별로 개념 설명·적용 문제·해설·정답표의 역할과 직접 확인한 요소를 함께 기록한다. 정답표를 개념 정리표의 관찰로 바꾸거나 문제편의 구획을 개념 설명·암기·복기 장치까지 확인한 근거로 쓰지 않는다. 공개 본문 표본과 로컬 근거를 실제 확보한 교재만 해당 확인 범주의 집계에 포함하며 링크 발견·전체 교재 다운로드와 구별한다. 공식 소개의 부분 이미지는 관찰 근거로 보존하되 쪽번호·전쪽 배치를 확인하지 못하면 별도의 부분 표본으로 기록한다. 이미지 조각 수를 본문 쪽 수로 더하거나 부분 표본만으로 전체 여백·밀도·문항 배열까지 확인했다고 쓰지 않는다.
5. **디자인 원리만 관찰 원장에 남긴다.** 교재별로 쪽 구성·정보 계층·핵심/주의/예시/복기·표/도식 배치·여백/글자/줄간격·복습 칸을 실제 쪽과 연결한다. 관찰 사실, 수치 측정/추정, 우리 자료에 적용할 제안과 효과 가설을 나눈다. 캡처는 승인된 로컬 조사 폴더에만 보관하고 견본/학습 PDF·Discord·iCloud에는 넣지 않는다. 외부 본문·도식·문항·고유 캐릭터·로고·브랜드 표현·전체 디자인을 가져오지 않는다. 재구성할 일반 원리와 배제할 고유 요소를 함께 적어 제작자의 복제 오해를 막는다.
6. **집계 단위를 고정해 원장에서 계산한다.** `과목 → 강사 → 교재/판본 → 접근 시도 → 열람 근거`를 고유 키로 연결한다. ISBN·공식 상품/교재 ID·서지로 같은 판본을 대응시키고 여러 링크·미러·캡처를 여러 권으로 세지 않는다. 교재·판본 종수와 물리 권수를 구분하고, SET를 대표 교재 한 종으로 세면 구성 권수는 별도로 표시한다. 쪽수는 실제 교재 ID·인쇄 쪽의 고유 쌍에서 계산해 양면이 보이는 한 뷰어 화면과 여러 번 캡처한 같은 쪽을 올바르게 구분한다. 식별이 불명확하면 임의 병합하지 말고 미확인으로 둔다. 강사 경로·복수 교재·서지 미확정 묶음이 섞인 후보는 항목 수로만 보고하고 권수 분모에 합치지 않는다. 선정 강사 수, 조사 대상 교재 수, 쪽 단위 본문 표본, 부분 표본, 비공개 제외, 기타 사유별 제외, 미확인/미처리를 각각 계산한다. 비공개 제외 0의 분모가 선정 교재인지 전체 후보인지 밝히고 미열람 자료까지 모두 공개라는 뜻으로 쓰지 않는다. 장부 분모와 상태 합계를 프로그램으로 대사하고 일부 과목이나 미조사를 0으로 채우지 않는다. 과목 합계뿐 아니라 선정 강사별 실제 본문 표본 수와 필요한 역할의 표본을 대사해 일부 강사의 미확보를 전체 합계로 가리지 않는다. 제외 장부에 교재와 강사 후보가 섞이면 실제 종류 필드로 나눈 뒤 교재 ID의 고유 집합을 계산한다. 선정 강사 교재·미선정 후보 교재·대체 조사 교재의 분모도 구분해 제외 총행수를 제외 권수로 보고하지 않는다. 목표가 미달이면 실제 조사 범위와 부족한 강사·교재·표본 역할을 드러낸다.
7. **총괄 인수와 부족분 보완을 구분한 뒤 실제 학습 쪽으로 후보를 만든다.** 조사 담당의 완료만으로 소비를 열지 말고 실제 출처·공개 열람/이용 조건·확보/제외 집계·고정 제출 경로를 확인한다. 승인상 별도 AI 검수가 없는 디자인 조사에 새 검수 단계를 추가하지 않는다. 부분 표본·서지·선정 범주에 미확인이 남으면 제출 기록의 인수와 전체 조사 기준 충족을 구분한다. 승인된 보완 카드에는 승계할 교재/쪽 ID·불변 근거, 미충족 필드, 허용할 추가 확인, 금지할 재조사, 완료·보류 조건을 고정한다. 선행 manifest·report·handoff의 실제 경로와 확인값을 시작 전에 대사하고, 승계 표본과 이번 실행의 새 본문 확보를 별도로 집계한다. 교재 식별자·발행 정보·시도 경로만 보완했다면 새 본문 확보는 0으로 보고하며, 기록 제출 완료를 표본 목표 해소로 바꾸지 않는다. 같은 미달로 새 조사 카드를 반복 생성하지 말고, 새 공개 근거·정상 경로·입력 또는 승인 범위의 변화가 있는지 확인한 뒤 필요한 범위만 재개한다. 과거 입력 시작 기록이 없을 때의 인수 한계와 새 스냅샷은 `source-grounded-wiki.md`의 제출물 인수 절차를 따른다. 부족분에 실제 의존하는 소비 단계만 대기시키고 독립 과목의 완료를 임의 선행으로 추가하지 않는다. 견본 입력은 승인된 불변 학습판의 PDF·원고·표/도식 내용·원문 자산·시간표·번호 대응과 인수한 조사 결과로 고정하고, 기존 스타일은 재사용이 명시된 계약에서만 시각 입력에 포함한다. 전후 비교가 승인된 계약에서는 전을 실제 원판 쪽, 후를 같은 내용에 후보 디자인만 적용한 쪽으로 만들며, 개념·표/도식·주의·복기·원문·해설 등 승인된 역할 쪽을 대응시킨다. 조사 근거 전용 재설계는 9번의 내용/시각 입력 분리 절차를 따른다. 공통 예제나 자리표시자를 실제 쪽 대신 쓰지 않는다. 원문 문항 자체는 손대지 않고 승인된 쪽의 주변 배치만 비교한다. 외부 미리보기 캡처와 독립 원본 파일은 견본 첨부에 섞지 않는다.
8. **번호 후보 선택 계약은 선택 빌드 대사 → 역할별 비교 → 추천 고정 → 첨부 확인 → 마스터 선택 순서로 처리한다.**
   - **다안 비교의 공통 내용팩을 먼저 잠근다.** 안별 쪽수와 전체 안 수를 승인 범위에서 고정하고, 비교할 개념·필수 문장/조건·복기 항목·표의 셀·도식의 의미/노드·문항/필요 공동 지문·원문 자산을 같은 목록으로 둔다. 여러 쪽짜리 옛 학습판 전체와 이번 짧은 비교팩을 혼동하지 않는다. 색·배치만 달라야 하는 계약에서는 안마다 요약하거나 조건을 빼지 말고, 내용 항목의 누락·추가와 원문 이미지의 RGB 보존·표시 영역/잘림을 구분해 대사한다.
   - **조합 고유성과 실제 구조 차이를 따로 검증한다.** 구성·제목 위계·강조·색 양·밀도·표/그림 위치를 구조화한 조합표에서 고유 튜플을 도구로 확인한다. 기준안의 고정 조건과 변경안에 요구한 변화를 따로 검사하고, 팔레트 재사용 최소 비중도 해당 변경안 집합을 분모로 계산한다. 실제 전체 쪽 개요와 필요한 확대 표본을 대조해 단 구성·여백·카드/세로 띠·표 위치가 실현됐는지 확인한다. 좌표는 같고 색만 바뀐 결과나 이름만 다른 조합을 구조 다양성으로 인정하지 않는다.
   - **선택 표식과 납품 목록을 일치시킨다.** 각 안 첫 쪽의 큰 번호·특징 한 줄, 그 안의 연속 쪽 범위, 별도 축 비교표의 번호/조합을 대응시킨다. 안별 쪽수와 전체 쪽수를 실제 PDF에서 확인하고, 통합 비교본과 별도 표를 요청받았으면 정확한 두 종류만 전달 목록에 둔다. 내부 렌더·진단·이전 빌드를 안 수나 납품 수에 더하지 않는다.
   - **전달 범위를 먼저 고정한다.** 인계의 현행 판본·선택 빌드·전달 PDF 목록을 대조한 뒤 파일별 쪽수·크기·SHA256과 원판 대응을 확인한다. 같은 제출 폴더에 보존된 이전 빌드·진단 PDF·렌더까지 모두 첨부 대상으로 세지 않는다. 실제 비교한 일차·원판 쪽·역할과 전체 학습판 재제작의 범위를 분리한다.
   - **필요한 시각 비교만 묶어서 수행한다.** 제작자가 남긴 전체 쪽 개요 이미지를 먼저 읽고, 후보별 개념 설명·표/도식·주의·복기·원문 주변·해설 대조표 중 추천 차이를 판별할 확대 표본을 묶어 확인한다. 표본은 실제 전달 PDF와 같은 빌드여야 한다. 개요만 본 쪽과 확대 판독한 쪽을 나누어 기록하고, 필요한 차이를 확인했으면 계약에 없는 전면 내용 검수를 추가해 선택 보고를 늦추지 않는다. 크기·배율·잘림 판단은 4절의 비교 기준을 따른다.
   - **근거와 추천을 현재 운영 기록에 고정한다.** 각 후보에 숫자 번호, 정확 견본의 파일/쪽/해시, 우선 강사·교재·관찰 쪽/URL·참고 방식, 우리 자료의 독자 설계, 장단점·제약을 연결한다. 일반 개념서는 보조로 표시하고 제작자 추천과 총괄 추천을 별도 필드로 둔다. 총괄은 실제 표본 비교 후 후보별 추천 여부·추천 번호 집합·보고 판본을 카드와 원장에 남겨 읽어 확인한다. 봉인된 제작자 파일의 추천 대기 표시를 고치거나 다시 봉인해 현재 상태를 맞추지 않는다.
   - **선택의 의미를 명확히 보고한다.** 완성형 후보 중 하나를 고르는 경우에는 한 번호 선택임을 밝힌다. 일부 요소를 섞으려면 조합·반영 범위를 별도 보고에 고정한 뒤 선택받는다. ‘총괄 추천대로’가 가리키는 정확한 집합, 추천의 절충점, 큰 병치 비교판의 확대 보기 방법·인쇄 미검증 범위를 함께 적는다. 본문이 보존한 과거 판본·컨펌 문구와 현행 운영 상태가 다르면 원문을 고치지 말고 비교판 안내나 캡션에서 구분한다.
   - **선택용 PDF만 전달하고 정확히 읽어 확인한다.** 현행 허용 전송 경로로 후보 번호·판본·학습/해설 구분·쪽수·추천 여부가 있는 캡션과 전달 목록의 PDF만 보낸다. 외부 캡처·독립 원문 이미지·원본 시험지·검증 기록은 섞지 않는다. 반환 메시지 ID별로 채널·작성자·본문·첨부 수/크기와 알림 플래그를 대조하고 첨부 집합·바이트 합을 도구로 계산한다. 조회에서 생략된 필드를 0이나 검증 성공으로 채우지 말고 확인한 항목과 미확인 항목을 분리한다. 전송 결과가 불명확하면 정확한 대상부터 읽고 중복 전송을 막는다. 캡션과 최종 선택 보고를 구분해 같은 보고 본문을 반복 게시하지 않는다.
   - **선택 이후만 실제 반영한다.** 사용자의 번호 선택 또는 ‘총괄 추천대로’는 그 보고에 고정된 집합에만 적용한다. 승인 뒤 추천 집합을 바꾸거나 미선택 후보를 함께 반영하지 않는다. 별도 실행 카드가 선택분만 새 양식에 반영하고 디자인 전용 이관의 내용 불변을 검증한다. 견본 제작 카드의 완료를 양식 채택·학습판 재제작·품질 승인으로 올리지 않는다. 새 학습판의 우선 전달·정확 판본 컨펌은 `learning-material-feedback.md` 9절을 따른다.
   - **선택안의 한 요소만 고칠 때는 다음 순서를 적용한다.**
     1. 최종 납품 선택표·handoff·실제 PDF의 판본/해시를 대응시키고, 선택 번호의 원본 SVG나 동등한 조판 입력·내용팩·원문 자산만 새 작업의 불변 입력으로 고정한다. 전체 비교팩이나 모든 후보를 다시 만들지 않는다. 후보 목록의 실제 자료형을 먼저 확인하며, 숫자 ID를 가진 `variants` 배열이면 `jq --argjson n "$selected_variant" '.variants[] | select(.id==$n)' "$variants_path"`로 한 행을 고르고 결과가 정확히 하나인지 검사한다.
     2. 새 쓰기 영역에서 선택안의 최소 배치·엔진만 재현하고, 변경 전 결과를 고정 원판과 대조한 뒤 요청한 부분만 수정한다. 옛 생성 코드를 원위치에서 실행하지 않는다. 출력·캐시 경로가 옛 실행 폴더에 고정돼 있으면 보존해야 할 입력을 덮어쓸 수 있기 때문이다.
     3. 실수 안내를 분리할 때는 기존 문구를 옮겨 자체 외곽·제목·본문이 있는 독립 주의 카드로 만들고, 원래 조건 카드에 실수 문구를 중복 남기지 않는다. 본문 크기·행간·폭·역할색은 유지하고 뒤 블록에 필요한 평행 이동만 기록한다. 판본·검수 전 표지·쪽번호 변경은 학습 내용과 구분해 목록화한다.
     4. 학습 블록의 문자열·공백·번호·개수, 표의 셀, 도식의 노드/연결을 원판과 대사하고 원문 이미지의 RGB 보존과 표시 크기·방향·전체 영역/무덮개를 따로 검증한다. 수정하지 않은 쪽은 학습영역의 조판 기록과 같은 DPI 렌더를 대조하되, 제출 메타표지를 제외한 범위를 명시한다. 지문이나 문항이 보이더라도 디자인 확인을 새 풀이·정답 판정으로 확대하지 않는다.
     5. 원판의 고정 하단 좌표를 새판의 무조건적인 상한으로 복사하지 말고 실제 도형·글자 끝과 용지/푸터 경계를 측정한다. 승인된 여백·판형 조건은 완화하지 않으며, 원판 재현용 진단 조건과 새판의 실제 잘림 검사를 구분한다. 필요한 공간이 없으면 글자를 줄이거나 쪽수를 바꾸지 말고 계약 충돌로 인계한다.
     6. 스타일 정의에 선택 원판·변경/불변 항목·후속 사용 경로를 고정하고, 선택표가 가리키는 수정 견본만 최소 대사해 먼저 첨부한다. 긴 봉인 인수와 추가 디자인 관찰은 선첨부 뒤에 처리한다. 실제 게시를 읽어 확인한 뒤 원카드·견본 카드·원장의 현재 게이트를 ‘번호 선택 완료·수정 견본 OK 대기’로 맞추고, 이미 보낸 비교팩은 다시 첨부하지 않는다.

9. **조사 근거 전용 재설계는 입력 분리 → 디자인 결정표 → 실제 내용 견본 → 양식 컨펌 → 학습판 재제작 순서로 처리한다.**
   - **허용 조사와 내용 원판을 따로 고정한다.** 현행 승인에 지정된 조사 비교표·적용 제안·관찰 원장과 manifest를 확인하고, 내용 보존용 학습판·원고·번호/시간표·원문 자산의 확인값을 별도 목록으로 남긴다. 옛 스타일·색 역할·후보 빌드·최근 역할 요약을 새 설계 근거로 쓰지 않도록 카드의 비목표에 명시한다. 과거 입력 파일이나 기록을 지워 이 분리를 만들지 않는다.
   - **조사 속 관찰과 옛 운영 가정을 분리한다.** 적용 제안에 기존 색 체계 유지나 폐기된 후보 선택 순서가 남아 있으면 관찰 사실·일반 배치 원리와 구분해 효력을 제외한다. 제안 원문은 보존하고 새 카드의 현행 지시에서 우선관계를 밝힌다. 내용 원고는 순수 내용 데이터로 옮겨 기존 CSS·색·간격 값을 조용히 상속하지 않으며, 자체 제작 도식의 의미와 시각 속성도 나눈다. 원문 문항의 보존 화소는 스타일 정리 대상으로 삼지 않는다.
   - **모든 시각 결정을 추적 가능한 표로 만든다.** 색 사용/역할, 단 구성, 본문·메모 여백, 제목·번호·소주제의 위계, 설명과 표/도식의 근접, 적용·복기·답 공간, 글자 크기·가로/세로 배율·줄 간격을 결정 항목으로 나눈다. 각 행에 채택 값·방식, 조사 자료와 교재·실제 쪽·관찰/제안 ID, 관찰 사실인지 제안인지, 다르게 재구성한 점과 한계를 적는다. 측정하지 않은 수치를 외부 교재의 값이라고 쓰지 않는다. 사용자가 컬러 피드백을 주면 색을 쓰는 방식의 관찰 근거와 독자적으로 고른 정확한 색값을 분리한다. 색 결정 행에 교재·쪽·관찰 ID, 새 기본색과 틴트, 소주제 띠·소제목·자체 도식 면·원문 밖 번호의 적용 위치, 브랜드 복제를 배제한 점과 미검증 한계를 연결한다. 스타일 데이터·결정표 본문·견본 PDF에서 같은 값을 사용하고, 종속 항목에 남은 흑백 설명과 무채색만 허용하는 자체검사 조건도 새 피드백에 맞춰 갱신한다. 과거 검사·판본·봉인을 고쳐 소급 통과시키지 않는다. 원문 이미지 안에는 새 색을 넣지 않으며 화면 대비나 인쇄 시뮬레이션을 실물 출력 검증으로 부르지 않는다. 명시적 컬러 요구와 근거가 모두 없는 항목에만 흑백 본문·얇은 회색 선 같은 중립 기본값과 ‘조사 근거 없음’을 적용한다. 같은 값이 옛 양식에도 있다는 이유만으로 재사용을 정당화하지 말고 독립된 근거·새 사용자 요구 또는 중립 기본값의 이유를 남긴다.
   - **내용 계약을 유지한 실제 쪽을 제출한다.** 설명·표/직접 도식·주의/수행 안내·빈 복기·원문 지문/문항·해설 대조표 등 승인된 역할을 실제 학습 내용으로 보여 준다. 자리표시자와 색만 바꾼 옛 후보로 대체하지 않는다. 직접 읽을 수 있는 최종 사용 크기의 견본 쪽을 포함하고 큰 병치 비교판만으로 가독성을 판정하지 않는다. 견본의 일차·원판 쪽·역할·쪽수와 전체 학습판의 미제작 범위를 적는다. 필요한 공동 지문과 정답/복기 기준 분리도 유지한다.
   - **승인된 견본과 결정표를 먼저 보고한다.** 전달 목록에 정확한 견본 PDF와 첨부가 승인된 디자인 결정표를 구분해 고정한다. 결정표를 검수 기록과 혼동하거나 원본·외부 캡처·진단 파일을 함께 보내지 않는다. 총괄은 필요한 디자인 표본과 근거 연결만 확인해 보고하고, 계약에 없는 AI 전면 검수를 앞세워 컨펌 요청을 늦추지 않는다. 하나의 새 양식에 대한 컨펌이면 그 판본의 OK 또는 피드백을 요청하며 폐기된 번호 후보를 다시 고르게 하지 않는다.
   - **양식 OK와 새 학습판 OK를 따로 연결한다.** 컨펌 전에는 제안 양식을 현행 선택 포인터에 채택하거나 전체 학습판 재제작을 시작하지 않는다. 양식 OK 뒤 같은 제작자에게 승인된 내용·문항·정답/해설·시간·번호·보류를 보존하는 디자인 전용 재제작을 배정한다. 새 학습판은 다시 우선 첨부하고 그 정확 판의 OK 뒤에만 AI 최종 오류 검사로 넘긴다. 사용자 피드백 반영과 AI 오류 수정의 회차를 섞지 않는다. 디자인 승인을 독립 위키 작업의 새 선행으로 추가하지 않는다.

## 8. 실행 없이 담당·모델을 일괄 정리한다

이 절은 사용자 대면 총괄의 관리 작업에 적용한다. 카드별 배정 변경을 작업자 실행이나 공급자 연결 시험으로 확대하지 않는다.

1. **대상과 변경 필드를 먼저 고정한다.** 승인된 ID의 형식·중복·고유 집합을 검사하고, 각 `show --json`의 본문·원래 모델 기록·실제 수행 이력을 읽는다. 제목이나 임시 모델 표만으로 일괄 분류하면 같은 제작자가 맡아야 하는 내용 정정을 조사형으로 잘못 넘길 수 있다. 이런 예외는 원값으로 남기고 이유를 보고한다. 기술 정정은 내용 정정과 구분하되, 새 담당·모델 배정으로 과거 실패·수정 예산을 초기화하지 않는다.
2. **변경 직전 보존 범위를 잡는다.** `.task`의 실제 키를 확인한 뒤 `.assignee`·`.model_override`·`.provider_override`만 승인된 변경 대상으로 분리하고, 나머지 task 필드와 `parents`·`children`·`runs`를 전후 대사한다. 명령 인자에 전체 댓글·사건 이력을 넣지 말고 표준입력에서 필요한 필드만 추린다. 작은 응답은 JSON으로 직접 비교하고, 확인값을 쓸 때는 전후 같은 정렬·직렬화 범위를 사용한다.

```bash
hermes kanban --board ksat-10000 show "$task" --json |
  jq -cS '{task:(.task|del(.assignee,.model_override,.provider_override)),parents,children,runs}' |
  sha256sum
```

3. **승인된 관리 명령만 순서대로 쓴다.** 설치된 `reassign --help`·`set-model --help`를 확인한다. 담당 변경이 승인됐을 때만 다음 첫 명령을 쓰고, 모델만 바꿀 카드는 `reassign`을 생략한다. 각 변경 뒤 정확한 카드를 다시 읽어 원하는 값과 보존 범위를 확인한다.

```bash
hermes kanban --board ksat-10000 reassign "$task" "$approved_profile" --reason "$approved_reason"
hermes kanban --board ksat-10000 set-model "$task" "$approved_model" --provider "$approved_provider"
hermes kanban --board ksat-10000 show "$task" --json
```

   - 실행 없는 정리에서는 `unblock`·`dispatch`·`reclaim`·`reassign --reclaim`을 덧붙이지 않는다. 배정 편집을 위해 먼저 상태를 풀면 네이티브 디스패처가 작업자를 시작할 수 있다. 상태가 승인 범위와 다르거나 명령이 거부되면 해당 변경을 보류하고, 상태 전환·DB 수정으로 통과시키지 않는다.
   - 카드별 모델 override는 다음 실행의 배정값이다. 이 값을 확인하려고 공급자를 호출하거나 기본 모델·fallback·로그인을 바꾸지 않는다.
4. **반영 댓글을 남기고 다시 읽는다.** 배정값 검증 뒤 승인된 우선관계를 한 줄 댓글로 전달하고, 정확한 본문·작성자·같은 댓글의 중복 여부를 확인한다. 제목·본문의 옛 담당·모델 이름은 이력으로 보존한다. 중간 오류 뒤 다시 들어왔으면 현재 값과 댓글부터 읽고, 성공한 재배정·모델 지정·댓글을 통째로 반복하지 않는다.
5. **배치와 전체 집합을 따로 검증한다.** 서로 다른 카드만 작은 독립 배치로 처리하고 각 성공 카드의 읽기 검증을 끝낸다. 마지막에는 요청 ID와 실제 확인 ID의 정확한 집합 일치, 변경·미변경·오류의 상호 배타성과 합계, 역할·모델·공급자별 수, 카드별 원래 상태를 도구로 대사한다. 미변경 예외는 담당·모델뿐 아니라 본문·연결·기존 이력도 보존됐는지 확인한다.
6. **변경 결과와 실행 여부를 분리해 보고한다.** 실제 변경 수, 바꾸지 않은 카드와 본문 근거, 상태·본문·연결 보존 결과를 짧게 보고한다. 알림 봇 표시 정리를 재시작 시점으로 미루라는 지시가 있으면 이번에는 구독을 바꾸지 말고 재시작 전 점검으로 남긴다. 배정 정리 완료를 착수·재개·독립 검수·품질 승인으로 표현하지 않는다.
